# V30 — проверка смысла PIM и итог ветки диагностики

## Что такое PIM

PIM = Preintegrated IMU Measurements — предынтегрированные измерения IMU.

В JT-Zero диагностические поля frontend CSV заполняются напрямую из `FrontendOutputPacketBase::pim_`:

- `pim_dt_s = pim.deltaTij()`
- `pim_dpx/pim_dpy/pim_dpz = pim.deltaPij()`
- `pim_dvx/pim_dvy/pim_dvz = pim.deltaVij()`
- `pim_droll/dpitch/dyaw = pim.deltaRij().rpy()`

Источник: `tools/live_mono_imu_500mm_hud_v2.cpp`, callback `installFrontendDebugCallback()`.

## Важное ограничение интерпретации

Эти величины описывают предынтегрированный IMU-интервал i→j, который несёт frontend output. Они не являются автоматически:

- перемещением между соседними строками backend CSV;
- исправленным метрическим перемещением после визуальной оптимизации;
- независимой оценкой пройденного пути.

Поэтому анализ `analyze_v29_pim_backend_consistency.py`, где `deltaPij()` напрямую сопоставлялся с соседним backend step, нельзя использовать как физическую проверку согласованности PIM↔backend.

## Что из предыдущих тестов остаётся валидным

1. Исправление ориентации T_BS почти полностью убрало ложный вертикальный наклон:
   canonical |Z| примерно 43.2 → 3.9 мм, наклон примерно 4.97° → 0.45°.
2. Горизонтальная абсолютная ошибка при этом практически не улучшилась:
   примерно 9.49 → 9.73 мм.
3. Поэтому T_BS — причина ложного Z, но не основная причина остаточной ошибки горизонтального расстояния.
4. Ошибка сильнее варьируется в конце движения, но прямой причинности от торможения, конечной скорости, IMU-ускорения или gyro не найдено.
5. Общие корреляции frontend quality с signed error сильно смешаны с направлением; внутри A→B и B→A они не сохраняют один знак.
6. Простое сравнение PIM с backend из V29 признано методологически неверным и не используется для выводов.

## Следующий цикл

После CHECK следующий цикл следует начинать не с очередного корреляционного скрининга, а с правильно синхронизированной декомпозиции факторов backend update:

- состояние до update;
- IMU-only predicted state на том же exact interval;
- visual measurement / mono direction на том же exact interval;
- optimized backend state после update.

Только такой лог позволяет определить, на каком этапе появляется ошибка масштаба.
